Why, and how it is checked

Why — the agent's own reasoning, checkable

Generated from the same state the decision used, for whatever configuration is selected. Every claim is verified by re-running the agent.

How a claim is verified, and why no language model is used

If an explanation says an hour would flip when the limit moves by 0.42 °C, the verifier moves the limit and checks that it does.

No language model is used, and VRAM is not the reason. This stage reports numbers the agent already computed — the one place a model is most likely to be wrong and least excusable. Deterministic generation plus verification beats generation plus hope.

How the bound is built — the arithmetic, run in front of you

A bound cannot promise more than n/(n+1). That ceiling is arithmetic, not a property of this method — at small n it is the ceiling, and not the model, that caps the figures below. More calibration days is the entire remedy.

Why an order statistic has a hard ceiling

The margin is not a fitted parameter. It is the k-th smallest of the agent's own past errors, at k = ⌈(n+1)(1−α)⌉. When that index exceeds the number of errors held, the largest one available is used instead, the guarantee is degraded, and the tiles below say so rather than reporting the nominal figure anyway.

The real bound, from the four real FortyGuard days

The real day-level residuals. Your browser sorts them and picks the k-th in front of you, then checks its own answer against the reference implementation — to exact float equality, on every build.
